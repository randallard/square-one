# 2026-08-15 (3) — touch hands, and a constant that had been carrying a ratio

_Documents `ed987a7`, and the `flattenSequence` commit before it._

Ryan, after S1's calls were wired into townage:

> start with partner up — they should hold hands — we say touch hands — beau right palm up
> and belle's left palm down — making sure hands in open position — so the characters need to
> be a bit closer together when partnered up

"A bit" turned out to be a factor of three.

## Measuring first, because "closer" is not a number

Against townage's default cast at its derived frame scale of 2.60:

| | world units |
|---|---|
| how far apart a `COUPLE_WIDTH` couple stood | **2.60** |
| where their inside hands meet | **0.82** |
| bodies actually touching | 0.52 |

`COUPLE_WIDTH` was `1` — the same as a facing pair — which was never thought about; it was
the obvious default when the couple formation was invented that morning, and nothing had
looked at it since. Now **a third**, which lands within a hair of hand contact for that cast.

## The engine cannot know the answer, so it takes one

The touching distance is a property of **bodies**: it depends on each dancer's shoulder
offset, which runs 0.2 to 0.46 across the shipped cast. `partnerUp` therefore takes an optional
width, and a third is the body-agnostic default — the ratio a caller would recognise rather
than a number fitted to one cast.

That is the ADR-0004 seam doing its job. The engine says *a couple stands hand in hand*; a
consumer with real bodies says *how far that is*.

## 🔴 And the constant had been carrying a ratio nobody had noticed

`TRADE_LANE` was `LANE_OFFSET` — the flat 0.15 that `pass` uses for Dosado's shoulder pass.
Reusing it read as thrift and was a category error: `LANE_OFFSET` is calibrated against a
**facing pair's one-unit separation**, so borrowing the number borrowed a ratio with it.

Invisible while a couple was a full unit wide. The moment the couple narrowed to a third, the
inside dancer's arc radius came out at **0.017** — a dancer spinning on the spot instead of
walking an arc. Now a proportion of the couple's own width.

**The general shape, and it is worth more than the fix:** a constant borrowed from one
formation and used in another is a ratio in disguise, and it stays invisible for exactly as
long as the two formations happen to be the same size. Nothing was wrong when it was written.

The Partner Trade spec's composition table now names the constants rather than the numbers
that fell out of a unit-wide couple — a table of literals would have gone stale silently,
which is precisely what the lane did.

## `insideHands`, and where the line is

A couple stands hand in hand: the beau's **right** and the belle's **left**, meeting between
them. *Which* hands is a fact about the formation and belongs here. *How* they are held — palm
up beneath, palm down above — is a rendering convention and stays with whoever draws them.

Derived rather than stored on `Couple`, because a stored copy is a thing that can disagree with
the positions it came from.

## `flattenSequence`, from the commit before

`createPerformance` takes one motion per dancer, so a sequence has to become a single
continuous path before it can be watched. Same concatenation `compose` does for blocks, one
level up.

The part worth a test is the **dropped waypoint**: each call's first repeats the previous
call's exit instant, so keeping it puts two on the same beat and a consumer interpolating
across a zero-length interval divides by zero. The symptom would be one bad frame at the seam
— not something a static read finds.

Momentum is the last call's rather than the sum. It describes how a dancer is moving at the
end, which is what the flow rules ask about a transition; accumulated rotation across a whole
sequence is F4's separate question, and answering both in one field would answer neither.

## Also

Three assertions moved from 6 and 9 decimal places to 5, with the reason written down: a third
is not representable and `geometry.round` quantises to 1e-6, so asserting tighter than the
engine's own granularity asserts the absence of a rounding scheme it chose on purpose.
